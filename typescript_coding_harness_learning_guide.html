Build a Coding Harness in TypeScript

The purpose is not to build the fanciest agent. The purpose is to understand the runtime around the model: tools, execution, permissions, context, Git, failures, tracing, and evaluation.

North-star milestone 
$ harness "fix the failing tests"

> Running tests...
> 2 failures
> Reading src/parser.ts
> Editing src/parser.ts
> Running tests...
> 14 passed

Changed: src/parser.ts
Reason: Parser incorrectly handled empty input.

Learning Principles

Build first, abstract second.
Add an abstraction only after the previous version creates a real problem.
Own the agent loop.
Do not let a framework hide tool invocation, observations, state, and stopping conditions.
Use mature agents as references.
Study how they solve problems after you have experienced those problems yourself.
Prefer boring infrastructure.
Node standard library first. Fewer dependencies means more of the harness remains visible.

Phase 1Node.js

Build a Command Runner

No AI yet. Run a command and capture stdout, stderr, exit code, duration, and working directory.

type CommandResult = {
  stdout: string;
  stderr: string;
  exitCode: number;
};

async function execute(
  command: string,
  cwd: string
): Promise<CommandResult>
Phase 2Tool model

Introduce Explicit Tools

type ToolCall =
  | { type: "read_file"; path: string }
  | { type: "write_file"; path: string; content: string }
  | { type: "shell"; command: string };

Implement read_file, write_file, list_files, and shell. The model should eventually request tools by structured intent—not execute code directly.

Phase 3Model API

Connect the Model

Keep this deliberately constrained: one model response, one tool invocation, then stop.

User: "Find the bug in this project"
        ↓
Harness sends instructions + tools + task
        ↓
Model requests read_file(package.json)
        ↓
Harness executes it
        ↓
Tool result returned
Phase 4Core harness

Build the Agent Loop

while (!finished) {
  const response = await callModel(history);

  if (response.finalAnswer) break;

  for (const call of response.toolCalls) {
    const result = await executeTool(call);
    history.push({ call, result });
  }
}

The exact SDK structures may differ. The learning target is the loop: reason → act → observe → repeat.

Phase 5Context engineering

Manage History and Context

Start with intentionally simple policies: system instructions + original task + recent interactions. Do not introduce embeddings yet.

Phase 8Filesystem security

Workspace Boundaries

All file operations must remain inside a configured project root. Learn path normalization, traversal protection, and symlink concerns.

/project          ✅ allowed
/project/src/a.ts ✅ allowed
../../etc/passwd  ❌ blocked
Phase 9Reliability

Timeouts and Failure Recovery

Handle hanging processes, excessive output, non-zero exits, malformed tool input, and cleanup.

type ToolResult =
  | { ok: true; output: string }
  | { ok: false; error: ToolError };
Phase 10Git

Make Git First-Class

Add typed Git operations rather than relying entirely on arbitrary shell commands.

git.status()
git.diff()
git.changedFiles()

This enables auditability, rollback, change inspection, and later evaluation.

Phase 14Compare abstractions

Study Frameworks After Building the Primitives

At this point, frameworks become educational because you can recognize what they abstract: runners, tools, sessions, guardrails, traces, handoffs, workspaces, and evaluations.

Useful comparison targets: OpenAI Agents SDK, Mastra, Codex, OpenHands.

First Milestone Definition of Done

Once this works reliably, you have a real coding harness. Everything after this is refinement, scale, safety, ergonomics, and evaluation.

Suggested Initial Repository Shape

code-harness/
├── src/
│   ├── main.ts
│   └── shell.ts
├── package.json
└── tsconfig.json

Start here. Do not begin with a large folder hierarchy. Let the architecture grow because the implementation demands it.

Later, it may naturally become:

src/
├── agent/
├── model/
├── tools/
├── workspace/
├── permissions/
└── telemetry/
This guide is intentionally architecture-first and framework-light. Progress checkboxes are stored locally in your browser using localStorage.
